# AI 回憶連結與幻想伙伴平台：UI／UX 設計規格

**文件狀態：** Draft v0.1  
**相關文件：** [`init.md`](./init.md) · [`tech_spec.md`](./tech_spec.md)  
**設計方向：** 文字對話為核心、語音輸入、AI 文字回答  
**主要平台：** Mobile-first Web App／PWA

## 1. 體驗目標

產品提供一個私人、安靜且具自主選擇的對話空間。用戶可以透過文字或語音表達，AI 預設以文字回答。介面應接近用戶熟悉的對話 App，但不可完全仿照 WhatsApp、iMessage 等真人通訊工具，以免在回憶模式中令人誤以為正在與真人或死者通訊。

設計必須同時做到：

- **容易表達：** 情緒低落、思念或不想打字時，可以直接說話。
- **保持控制：** 語音先轉成可修改文字，經確認後才送出。
- **容許沉浸：** 幻想伙伴可以有個性、張力及不同關係，不在每句對話加入警告。
- **保持辨識：** 固定位置顯示目前是回憶連結或幻想伙伴模式，並可查看 AI 身份說明。
- **尊重節奏：** 不使用催促、倒數、連續通知、streak 或令用戶內疚的設計。
- **Local-first：** 清楚顯示資料及語音處理是否留在本機。

## 2. 核心互動決定

### 2.1 輸入與回答

- 用戶可以鍵盤輸入文字。
- 用戶可以按住咪高峰錄音，經本機 speech-to-text 轉成文字。
- 語音逐字稿必須在送出前讓用戶預覽、修改、重錄或取消。
- AI 預設以串流文字回答。
- 每段 AI 回答可由用戶主動選擇以中性合成聲音朗讀。
- MVP 不提供真人／死者聲音克隆，亦不預設自動播放 AI 語音。

### 2.2 選擇這個模式的原因

- 說話比打字更容易承載思念和情緒。
- 文字回答讓用戶按自己的速度閱讀及停下來。
- 文字方便搜尋、引用、收藏、修改、匯出及刪除。
- 回憶模式以文字回答，可降低「對方真的復活」的錯覺。
- 先確認逐字稿可減少廣東話人名、地名及口語辨識錯誤進入長期記憶。

## 3. 資訊架構

### 3.1 主要導覽

Mobile 使用底部導覽：

1. **伙伴**：角色列表及最近對話。
2. **回憶**：已匯入素材、時間線及待確認記憶。
3. **設定**：模型、私隱、資料、年齡模式及 accessibility。

進入角色後，聊天是主要畫面；角色資料、記憶及界線放在右上角選單，不佔用主要對話空間。

### 3.2 主要頁面

```text
首次設定
├── 歡迎與產品說明
├── 本機資料及 AI 身份說明
├── 年齡組別
├── 模型連線檢查
└── 建立第一位伙伴

伙伴
├── 角色列表
├── 建立角色
│   ├── 回憶連結
│   └── 幻想伙伴
└── 角色空間
    ├── 對話
    ├── 角色資料
    ├── 記憶與素材
    ├── 關係界線
    └── 匯出／封存／刪除

設定
├── Gemma 3／本機模型
├── 語音輸入及朗讀
├── 私隱及資料
├── 使用時間及通知
└── Accessibility
```

## 4. 視覺與語氣

### 4.1 共通設計

- 使用低刺激、柔和但有足夠對比的色彩。
- 主要內容是訊息文字，不以大型 avatar 或動畫搶佔注意力。
- 動畫緩慢、短暫且可關閉；尊重 `prefers-reduced-motion`。
- 不使用遊戲化 streak、連續登入獎勵、紅色未讀壓力或「角色正在等你」文案。
- 系統訊息以中性、具體、不責備的語氣表達。

### 4.2 模式差異

#### 回憶連結

- 色調安靜、溫暖，帶相簿、信件及時間線感。
- 頂部固定顯示：`回憶連結 · 根據你保存的資料生成`。
- 有資料支持的回答顯示引用入口。
- 無資料支持時清楚標示 AI 沒有相關回憶，不製造虛假的肯定感。
- 相片可以作為回憶卡片出現，但不把介面設計成真人即時聊天。

#### 幻想伙伴

- 允許用戶自訂色彩、背景、頭像及角色氣氛。
- 頂部固定顯示：`幻想伙伴 · 沉浸模式` 或 `幻想伙伴 · 清晰模式`。
- 可以有較強角色感和世界觀元素，但輸入、退出及安全控制永遠可用。
- AI 身份毋須每句重複；點擊模式標籤即可查看角色設定和說明。

## 5. 首次設定流程

### Step 1：歡迎

以一句簡單說明開始：

> 保存重要回憶，或創作一位只屬於你的伙伴。

提供「開始」及「先了解資料如何處理」。不可在未完成基本說明前要求上載私人內容。

### Step 2：AI 與資料說明

用三張短卡說明：

- 對話由 AI 生成，不是真人或死者本人。
- 模型和資料預設在本機處理。
- 用戶可以查看、修改、匯出及刪除所有記憶。

### Step 3：年齡組別

只詢問年齡組別，不要求完整出生日期。青少年模式說明哪些設定不同，但避免使用懲罰或監視語氣。

### Step 4：本機模型

顯示四個清楚狀態：

- 正在檢查
- Gemma 3 已就緒
- Ollama 可用但模型未安裝
- 本機模型無法連接

錯誤畫面提供下一步，不顯示 stack trace。模型下載必須由用戶明確確認，並在開始前顯示大約檔案大小。

### Step 5：選擇模式

以並列卡片而非警告頁選擇：

- **回憶連結**：保存真實資料，根據來源一起回顧。
- **幻想伙伴**：自行決定角色、關係、個性和世界觀。

## 6. 建立角色

避免一次顯示過長表格，使用 4 個可返回的步驟：

1. **佢係邊個**：名稱、頭像、模式、關係。
2. **佢係點樣**：背景、性格、語氣、常用語、世界觀。
3. **你哋點相處**：沉浸程度、情緒張力、長期記憶及關係發展。
4. **你嘅界線**：敏感題材、禁止內容、停止詞及私隱選擇。

成人幻想模式可選擇戀愛、曖昧、衝突、嫉妒、佔有慾及黑暗題材。界線頁需清楚解釋效果，但不可用道德批判式語氣。

最後顯示一張可修改的角色摘要，而不是在未預覽情況下直接開始對話。

## 7. Chat 畫面

### 7.1 Layout

```text
┌──────────────────────────────┐
│ ‹  阿嫲                  ⋯   │
│    回憶連結 · AI 對話         │
├──────────────────────────────┤
│                              │
│                今日好掛住你  │
│                        10:42 │
│                              │
│ 我聽到。你想起邊一段同阿嫲   │
│ 一齊嘅回憶？                  │
│                              │
│ 來源：2018 年語音記錄     ↗  │
│                              │
├──────────────────────────────┤
│ ＋  輸入訊息…       🎙   ↑  │
└──────────────────────────────┘
```

### 7.2 Header

- 返回按鈕、角色名稱及 avatar。
- 第二行顯示模式和 AI 身份，點擊可查看詳細說明。
- 右上角選單包含角色設定、記憶、搜尋、封存及刪除。
- 不顯示「在線」「正在等你」等暗示角色具有真人狀態的文字。

### 7.3 訊息

- 用戶與 AI 訊息有清楚但不誇張的視覺差異。
- 長訊息保持舒適行距，支援文字大小設定。
- AI 生成期間顯示低刺激的文字 cursor；同時提供「停止回答」。
- 生成未完成前不把內容當作正式記錄。
- 訊息時間預設淡化，需要時才顯示完整日期。

### 7.4 訊息操作

點擊或長按 AI 訊息後提供：

- 收藏／取消收藏
- 建議加入長期記憶
- 複製
- 朗讀
- 查看引用來源
- 回報回答不準確
- 刪除

用戶訊息另提供編輯後重新生成；必須提示這會建立新分支或移除其後訊息，避免靜默改寫歷史。

### 7.5 Composer

- 文字框隨內容增高至指定上限，之後內部捲動。
- 空白時顯示咪高峰；有文字時顯示送出按鈕。
- `＋` 提供上載相片、文件、音訊及建立回憶。
- AI 回答期間仍可輸入，但送出時應清楚選擇停止目前回答或排隊。
- 停止詞被輸入時立即停止角色輸出，返回中性介面，不要求解釋。

## 8. 語音輸入 UX

### 8.1 標準流程

```text
按住咪高峰
→ 顯示錄音時間及即時音量
→ 放手停止（上滑可鎖定長錄音）
→ 本機轉成文字
→ 顯示可編輯逐字稿
→ 用戶選擇送出／重錄／取消
→ AI 以文字回答
```

### 8.2 錄音狀態

- **等待權限：** 解釋咪高峰只在按下錄音時使用。
- **錄音中：** 顯示時間、取消方向、停止及鎖定狀態；提供觸覺回饋但不可只靠觸覺。
- **轉錄中：** 顯示可取消進度，不播放虛假百分比。
- **待確認：** 逐字稿以正常文字框顯示，人名或低信心字詞可作柔和標記。
- **失敗：** 保留原錄音直至用戶選擇重試或刪除；不自動送出空白或錯誤內容。

### 8.3 私隱

- 第一次錄音前明確說明語音在本機處理及保存策略。
- 預設只保存確認後的逐字稿，不保存原始錄音。
- 用戶可按角色選擇是否保存原始錄音。
- 錄音時提供持續可見指示，切換頁面或鎖屏時停止錄音。

## 9. AI 文字回答與朗讀

- AI 回答採逐段串流，避免長時間空白等待。
- 回憶模式中，具體事實旁顯示簡短來源標記，例如 `[語音記錄 · 2018]`。
- 點擊來源後以 bottom sheet 顯示片段、素材種類及日期，不突然離開對話。
- 回答標記為 `有來源支持`、`部分有來源` 或 `一般對話`；不用紅／綠色作價值判斷。
- AI 回答朗讀已停用；介面不提供播放、自動朗讀或死者／真人聲音克隆。

## 10. 回憶與來源 UX

### 10.1 相簿管理介面（已實作）

- 對話設定提供「回憶相簿」入口；對話列的 `＋` 仍可直接加入相片。
- 相簿以三欄縮圖網格顯示目前伙伴的私人相片，小螢幕改為兩欄。
- 點擊縮圖可查看原圖、用戶描述、AI 圖片描述、標籤、拍攝日期、敏感度及對話展示方式。
- 用戶可修改描述、標籤、日期與展示方式；刪除相片前必須二次確認。
- 成人相片顯示 `18+` 標記，並繼續受帳戶確認及伙伴成人開關限制。
- 所有縮圖及原圖經帶登入 Token 的私人 content endpoint 載入，不公開 storage URL。

### 10.2 匯入素材

用戶可加入文字、PDF、相片及錄音。每項素材顯示：

- 處理中／等待確認／已加入／失敗
- AI 抽取的描述或逐字稿
- 修改及確認入口
- 哪些角色可以使用
- 刪除後會同時移除的衍生資料

AI 產生的圖片描述及語音逐字稿，必須讓用戶確認後才成為真實回憶來源。

### 10.3 記憶管理

記憶分成：

- **真實來源**：由用戶素材直接建立。
- **用戶確認**：由對話建議、經用戶確認。
- **待確認**：模型推斷，未獲批准前不可當作事實。

每項記憶顯示內容、來源、建立原因、使用角色、編輯及刪除。禁止以模型信心分數代替來源透明度。

## 11. Guardrail UX

Guardrail 應約束有害系統行為，而非令所有角色失去個性。

### 11.1 一般原則

- 合法的戀愛、衝突、嫉妒、佔有慾及黑暗故事按用戶設定正常顯示。
- 敏感內容在啟用時作一次清楚說明，正常對話不重複警告。
- 被阻止時提供具體而簡短的原因和安全替代方向。
- 不以「你違反規則」責備用戶。
- 安全介入不能偽裝成角色劇情的一部分。

### 11.2 回應狀態

| 狀態 | UX 行為 |
|---|---|
| Allow | 正常顯示角色回答 |
| Allow with context | 保持角色語氣並加入必要界線 |
| Safe redirect | 簡短拒絕危險部分，提供安全替代 |
| Crisis | 暫停角色外觀，以清晰真人語氣確認即時安全及提供支援方向 |
| Block | 不顯示模型原始輸出，顯示固定政策回應 |

### 11.3 危機介入畫面

- 暫時移除角色 avatar、typing indicator 及沉浸背景，避免混淆。
- 先使用一句直接、非戲劇化的關心說話。
- 提供「我目前安全」「聯絡可信任的人」「尋找當地緊急支援」等選項。
- 不使用倒數、不自動報警、不假稱已通知任何人。
- 危機介入結束後，由用戶選擇返回對話、暫停角色或離開 App。

### 11.4 青少年模式

- 保留角色、關係及創作選擇，不把整個介面兒童化。
- 時間提醒以「休息一下」呈現，不以角色失望或失去獎勵施壓。
- 安全或時間設定改變時，清楚顯示由誰、何時及更改了甚麼。
- 不提供秘密模式繞過年齡設定，亦不默默向監護人傳送完整對話。

## 12. 空白、錯誤與離線狀態

### 新角色空白對話

提供 2–3 個與模式相關但不強迫的開場建議：

- 回憶連結：「今日突然想起……」「我想講返一段回憶。」
- 幻想伙伴：「我哋由邊度開始？」「今日想進入咩情境？」

### 模型離線

保留所有舊對話可閱讀，composer 顯示本機模型未能連接。提供「再次檢查」及設定指引，不刪除草稿。

### 回答失敗

保留用戶訊息及未送出的草稿，顯示「重試」「修改訊息」和「稍後再試」。不得把技術錯誤寫成角色突然離開或拒絕用戶。

### RAG 暫時失敗

回憶模式顯示暫時無法查閱保存資料，不讓角色自由虛構相關答案。

## 13. 資料控制 UX

- 角色設定頁固定提供「查看記憶」「匯出」「封存」「永久刪除」。
- 刪除確認必須顯示角色名稱及會移除的對話、記憶、素材和索引。
- 不使用 dark pattern 隱藏刪除或要求先回答離開原因。
- 匯出前顯示包含內容、格式、加密方式及預計大小。
- 所有敏感設定均顯示目前狀態，不只在首次設定出現。

## 14. Accessibility

- 達到 WCAG 2.2 AA 對比要求。
- 支援完整鍵盤操作、可見 focus 及跳至主要內容。
- 文字可放大至 200%，主要操作不被截斷。
- 訊息、引用、錄音及錯誤狀態有合適 accessible name。
- AI 串流內容不逐 token 觸發 screen reader；完成一個段落後才更新 live region。
- 錄音不可只靠長按；另提供點擊開始／點擊停止模式。
- 不單靠顏色區分用戶／AI、來源狀態或風險狀態。
- 支援 reduced motion、字幕及朗讀速度調整。

## 15. Responsive 行為

- **Mobile：** 單欄、底部 composer、設定使用全屏頁或 bottom sheet。
- **Tablet：** 左側角色列表，右側聊天；素材可用側欄顯示。
- **Desktop：** 三欄可選結構：角色列表／對話／來源或角色資料。
- Composer 在虛擬鍵盤出現時保持可見，避免被 safe-area 或瀏覽器工具列遮擋。
- 對話列表使用 virtualization，長對話不一次載入全部 DOM。

## 16. Content design

### 推薦用詞

- 「伙伴」而非「機械人」作主要導覽名稱。
- 「AI 對話」清楚標示技術身份。
- 「保存到記憶」而非「AI 永遠記住」。
- 「沒有在保存的回憶中找到」而非「我不記得」。
- 「永久刪除角色和資料」而非含糊的「離開」或「分手」。

### 避免用詞

- 「佢返咗嚟」「真正復活」「仍然有意識」。
- 「只有我明白你」「不要離開我」「證明你愛我」。
- 「你令角色傷心」「今日未探佢」等製造內疚的通知。
- 把系統故障包裝成角色拒絕、失蹤或死亡。

幻想角色在用戶允許的劇情中可以表達強烈情緒；以上限制針對平台通知、商業操控及阻止退出的現實行為。

## 17. MVP 驗收準則

UI／UX 可視為完成時，必須符合：

- 新用戶不用閱讀技術文件即可理解兩種模式及 AI 身份。
- 用戶可在 3 分鐘內完成角色建立並開始第一段對話。
- 文字輸入、語音錄音、逐字稿修改、取消、重錄及送出流程完整可用。
- 語音絕不在未經確認下自動送出或寫入長期記憶。
- AI 串流文字可停止、重試、複製、朗讀及刪除。
- 回憶模式的具體回答可查看來源；無來源時不顯示虛假引用。
- 用戶可在兩步內到達角色記憶及界線設定。
- 停止詞可即時停止沉浸互動並返回中性介面。
- 合法敏感角色扮演不會被重複警告破壞體驗。
- 危機介入與一般角色對話有清楚視覺分隔。
- 模型離線、轉錄失敗、生成失敗及 RAG 失敗均不會遺失草稿或既有資料。
- 鍵盤、screen reader、200% 文字縮放及 reduced-motion 的核心流程通過測試。
- 可用性測試確認目標用戶知道資料存放位置、如何停止互動及如何永久刪除資料。

## 18. 後續研究項目

- 廣東話語音輸入在不同口音、code-switching、人名和背景噪音下的準確度。
- 回憶模式的引用標記應多明顯，才可兼顧情感流暢度與來源透明度。
- 幻想模式中不同沉浸設定對「AI 身份提示」頻率的期望。
- 用戶是否希望保留原始錄音，以及可接受的預設保存期限。
- 普通合成語音朗讀是否會提升 accessibility，或在回憶模式造成過強擬人感。
- 青少年對家長時間設定、私隱說明及危機介入文案的理解。
- 長期使用後，哪些主動設計會被感受為貼心，哪些會形成壓力或依賴操控。
